# VIE 환산·예약·정산 정책

## 1. 적용 범위

- 제공자: OpenAI
- 모델: `gpt-6.1-terra`
- 처리 방식: Standard 텍스트 요청
- 환산 정책 버전: `terra-v1`
- 기준일: 2026-11-12

다른 모델·처리 등급·유료 도구·이미지·음성 비용은 현재 환산 정책에 포함하지 않는다. 도입 시 해당 과금 항목을 지원하는 정책을 추가한다.

## 2. 환산 기준

API 사용 비용에 비례해 VIE를 차감한다.

- 1 USD = 10,000 VIE
- 기본 제공량 20,000 VIE = API 사용 비용 2 USD 상당
- 평균 사용량을 고정 차감액이나 예약 기본값으로 사용하지 않는다.

| 구분 | 100만 토큰당 비용 | 토큰당 VIE |
|---|---:|---:|
| 일반 입력 | $1.00 | 0.01 |
| 캐시 읽기 | $0.05 | 0.0005 |
| 캐시 쓰기 — 30분 | $1.25 | 0.0125 |
| 캐시 쓰기 — 12시간 | $2.50 | 0.025 |
| 출력 | $5.00 | 0.05 |

가격 근거: [OpenAI 공식 모델 요금](https://developers.openai.com/api/docs/models/gpt-6.1-terra)

전체 입력이 272,000토큰을 초과하면 요청 전체의 입력·캐시 비용에 2배, 출력 비용에 1.5배를 적용한다.

## 3. 실제 사용량 계산

일반 입력 토큰은 전체 입력에서 캐시 읽기와 캐시 쓰기 토큰을 제외해 계산한다.

```text
일반 입력
= 전체 입력 - 캐시 읽기 - 30분 캐시 쓰기 - 12시간 캐시 쓰기

최종 차감 VIE
= 유형별 토큰 사용 비용의 합계(USD) × 10,000
```

- 캐시 읽기·쓰기 토큰을 일반 입력으로 중복 계산하지 않는다.
- 출력은 제공자가 보고한 과금 대상 총출력 토큰을 사용한다.
- 총출력에 포함된 추론 토큰을 다시 더하지 않는다.
- 사용량 누락을 0으로 간주해 성공 정산하지 않는다.

캐시 계산 근거: [OpenAI 공식 캐시 사용량 설명](https://developers.openai.com/api/docs/guides/prompt-caching)

## 4. 정밀도와 검증

- 계산 타입: `BigDecimal`
- DB 저장 타입: `numeric(18, 6)`
- 중간 계산에서는 반올림하지 않는다.
- 최종 VIE 합계에서 소수점 6자리까지 `HALF_UP`으로 반올림한다.
- 음수·저장 범위 초과·잘못된 캐시 분류 합계는 거절한다.
- 엔티티에 전달한 수량을 저장하기 위해 추가로 반올림하지 않는다.

## 5. 예약 정책

AI 호출 전에 입력 토큰 상한과 최대 출력 토큰으로 예약량을 계산한다.

- 입력 전체가 가장 비싼 12시간 캐시 쓰기로 처리되는 경우를 상한으로 사용한다.
- 긴 문맥 할증 여부도 입력 상한을 기준으로 계산한다.
- 입력 상한에는 시스템 프롬프트와 대화 기록을 포함한다.
- 최대 출력 토큰은 실제 AI 요청의 출력 제한과 일치해야 한다.
- 예약량은 최종 차감액이 아니다.

```text
가용 잔여량 = 제공량 - 사용량 - 활성 예약량
```

잔여량이 부족하면 예약을 거절한다. 예약량 증가와 새 AI 요청 저장은 같은 트랜잭션에서 처리하며, 커밋에 성공한 뒤 AI를 호출한다.

확보한 이용 주기가 요청 시작 전에 만료됐다면 예약을 거절하고, 현재 주기를 다시 확보하도록 한다.

## 6. 성공·실패·결과 불명확 처리

### 성공

같은 트랜잭션에서 다음 변경을 반영한다.

1. 실제 토큰 사용량과 최종 차감액 기록
2. 해당 요청의 활성 예약량 해제
3. 이용 주기의 사용량 증가
4. 요청 상태를 `SUCCEEDED`로 변경

실제 차감액이 예약량을 초과하면 임의로 잘라 차감하지 않는다. 정산을 거절하고 기존 처리 상태와 예약량을 유지해 별도 확인 대상으로 남긴다.

### 확정 실패

같은 트랜잭션에서 요청을 `FAILED`로 변경하고 해당 예약량을 해제한다. 최종 차감액은 0이다.

제공자 비용이 발생했더라도 실패 요청에 차감하지 않은 비용은 운영자가 부담한다.

### 결과 불명확

타임아웃·연결 끊김·처리 기한 경과만으로 실패를 확정하지 않는다.

- 처리 상태와 활성 예약량을 유지한다.
- 같은 요청을 자동으로 다시 AI에 전송하지 않는다.
- 성공이나 실패가 확인된 뒤 정산한다.
- 결과 확인·복구 절차의 호출 연결은 실제 AI 연동 단계에서 구현한다.

## 7. 주기·버전·동시성

- 정산은 현재 이용 주기가 아닌 요청에 저장된 원래 이용 주기에 적용한다.
- 새 주기가 시작돼도 이전 주기의 사용량과 예약량을 초기화하지 않는다.
- 생성 시 환산 정책 버전을 저장한다.
- 지원하지 않는 제공자·모델·정책 버전은 현재 단가로 임의 정산하지 않는다.
- 요율을 변경할 때는 새 정책 버전을 추가하고 이전 정책의 해석 기준을 보존한다.

요청과 이용 주기의 `@Version` 및 DB 제약으로 동시 변경을 검증한다. 충돌 시 트랜잭션 전체를 롤백한다.

완료된 요청의 재완료는 거절해 추가 차감·예약 해제를 방지한다. 낙관적 락 충돌 후에는 새 트랜잭션으로 작업을 재시도해야 하며, 정산 재시도를 위해 AI를 다시 호출하지 않는다. 현재 Command에는 자동 재시도 기능이 없다.

AI 응답을 기다리는 동안 예약·정산 트랜잭션이나 DB 락을 유지하지 않는다.
